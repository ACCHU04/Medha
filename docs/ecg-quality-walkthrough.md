# ECG Digitization — Manual Quality Walkthrough

**Feature:** Paper ECG digitization (Feature 4)
**Status:** Manual acceptance checklist
**Date:** 2026-08-11

## Scope of this checklist

This walkthrough verifies that the browser digitization pipeline behaves as
intended across representative inputs. It uses **synthetic** sample images
generated by `ambulance-simulator/ecg-samples.js` (painted grids + a repeating
PQRST waveform) — no clinical claim is made, and results are **not** a
diagnosis. A real-photo capture set is the future manual gate (see the last
section); until then these synthetic fixtures stand in for it.

## How to run

1. Start the backend: `uvicorn app.main:app --reload --port 8000`.
2. Open `http://127.0.0.1:8000/ambulance-simulator/` and log in as `paramedic1` / `s3curepass`.
3. Create a patient + an emergency case (the **DIGITIZE & SEND** button needs a case).
4. In the **PAPER ECG** card, pick a variant from the **Sample** dropdown and click **LOAD SAMPLE**.
5. Read the status line and the two canvases (photo + extracted trace).
6. Tick the matching **pass** box below.

## Acceptance criteria per variant

| Variant | Expected status line | Expected trace canvas | DIGITIZE & SEND | Pass |
|---|---|---|---|---|
| `clean` | `Grid 8 px/mm · 50 samples · quality OK` | Continuous PQRST-like trace, full width | Enabled | ☐ |
| `blurry` | `Grid 2 px/mm · 200 samples · quality WARN (low contrast, blurry)` | Trace present but noisy | Disabled | ☐ |
| `dark` | `No ECG grid detected — quality WARN (too dark, low contrast, blurry)` | Hidden | Disabled | ☐ |
| `gridless` | `No ECG grid detected — quality WARN (washed out)` | Hidden | Disabled | ☐ |
| `low-contrast` | `No ECG grid detected — quality WARN (low contrast, blurry)` | Hidden | Disabled | ☐ |

> Note: the **DIGITIZE & SEND** button is intentionally gated on
> `quality.checks_passed` — only inputs that pass the automated quality check
> can be transmitted. That is the intended behaviour of the quality gate, not a
> bug.

## Checks

- [ ] `clean` digitizes and produces a plausible full-width trace
- [ ] `blurry` is flagged as a warning and never sent
- [ ] `dark` is flagged and never sent
- [ ] `gridless` is flagged and never sent
- [ ] `low-contrast` is flagged and never sent
- [ ] The two preview canvases show the photo and (when applicable) the trace
- [ ] After **DIGITIZE & SEND** on `clean`, the hospital dashboard shows the
      record under **ECG RECORDS** (photo + trace + "Decision-support only")
- [ ] `node --check` passes on `ecg.js`, `ecg-samples.js`, and `app.js`

## Real-photo future gate (not yet certified)

Synthetic fixtures validate the pipeline deterministically. Before any
accuracy claim is made, a future manual gate must run on real photographs:
(a) a clean, flat, well-lit paper ECG, (b) a blurred/out-of-focus shot,
(c) a dimly lit shot, (d) a shot without visible grid, (e) a skewed/perspective
shot. Capture guidance UI (alignment/focus/light hints) is a known requirement
and out of scope for this feature.

## Clinical boundary

This feature digitizes and transports a waveform record. It does **not**
diagnose, classify rhythms, or interpret the trace. All clinical use is
decision-support only; the dashboard displays the disclaimer
"Decision-support only, not a diagnosis."
